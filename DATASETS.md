# Datasets and reference models

EquiLead trains on a **synthetic, reproducible HELOC dataset** generated by `synth_data.py`. No real applicant data is
used anywhere. This document compares the datasets and modelling choices of the three reference repositories that were
studied, and explains why none of their data is used directly.

> None of the reference datasets describes U.S. home-equity lending. Treat every external dataset as research material
> only. EquiLead does not claim a validated U.S. HELOC model.

## Comparison of the reference repositories

| Aspect | Aegis-Credit | Explainable-Credit-Risk-Scoring | CreditIQ |
|---|---|---|---|
| Code licence | MIT | MIT | **No licence file** → ideas only, no code copied |
| Dataset | Synthetic consumer-credit generator (CC0 in the repo) | UCI *Default of credit card clients* (Taiwan, 2005; 30,000 rows) | "Credit Risk Benchmark Dataset.csv" (Give-Me-Some-Credit style; licence unclear) |
| Origin | Programmatically generated | UCI Machine Learning Repository, CC BY 4.0 | Kaggle-derived; provenance not documented in the repo |
| Target | Synthetic default flag | `default payment next month` (binary) | `SeriousDlqin2yrs` (90+ days delinquent within 2 years) |
| Features | Income, debt ratios, credit history, employment, loan terms | Credit limit, sex, education, marriage, age, 6 months of bill/payment history | Revolving utilisation, age, past-due counts, debt ratio, income, open lines, dependents |
| Missing values | None (generated) | None | `MonthlyIncome` and `NumberOfDependents` missing; imputed with medians |
| Class imbalance | Controlled by the generator | ~22% positives | ~7% positives; class weights / scale_pos_weight |
| Leakage risk | Low; derived ratios recomputed from raw inputs (feature contract) | Low; payment history precedes the target month | Moderate; past-due counts are close relatives of the target; clipping thresholds must be fitted on training data only |
| Protected / proxy variables | Kept out of features; separate fairness columns | **Sex, marriage, age are model features** — unacceptable for lending use | Age is a feature; used afterwards for an age-band disparate-impact check |
| Algorithms | Logistic regression, tree ensembles, calibration | Logistic regression (+ fairlearn selection-rate metrics) | XGBoost + SHAP |
| Validation | Stratified partitions incl. calibration split; band validation; threshold economics | Train/test split | 5-fold cross-validation |
| Metrics | ROC-AUC, PR-AUC, Brier, calibration, cost curves | Accuracy, ROC-AUC, selection-rate difference | ROC-AUC, precision/recall at threshold 0.4 |
| Fairness | Selection-rate and error-rate parity, small-group warnings | Selection rate by sex/age via fairlearn | Age-band disparate impact ratio |
| HELOC applicability | Consumer credit, not secured lending; no property, LTV or CLTV | Credit-card behaviour; no income verification, property or loan purpose | Unsecured consumer credit; no collateral fields |

### What EquiLead took from each (ideas, not code)

* **Aegis-Credit**: a feature contract that recomputes derived ratios from raw inputs at scoring time; separate
  train / calibration / test partitions; isotonic calibration; threshold analysis with explicit cost assumptions;
  validating that observed default rates rise monotonically across risk bands; a workflow with an append-only record.
* **Explainable-Credit-Risk-Scoring**: an interpretable logistic scorecard next to tree models; selection-rate
  metrics by group; the reminder that protected attributes must never be model features.
* **CreditIQ**: XGBoost with SHAP TreeExplainer for tree models; stratified 5-fold cross-validation; fitting outlier
  clipping thresholds on the training split only; a disparate-impact check across demographic bands.

## EquiLead's synthetic HELOC dataset

* Generator: `synth_data.py` (`synthetic-heloc-v1`), seed `20260916`, 12,000 rows by default. `python synth_data.py`
  writes `heloc_synthetic.csv`; `train.py` generates the same rows in memory.
* Licence: **CC0 1.0** for the generated data and the generator (it contains no third-party data).
* Inputs mirror the intake form: income (stated and verified), employment, monthly debt, credit score, history,
  delinquencies, inquiries, property value, mortgage balance, requested amount, occupancy, property type, purpose,
  term, rate, reserves, documents. Derived features (LTV, CLTV, DTI, payment, reserves months, documentation
  completeness) are computed by `calculations.py`, the same code used at scoring time.
* Target: `defaulted_24m`, drawn from a documented logistic model of CLTV, DTI, credit score, delinquencies,
  inquiries, reserves, employment, occupancy and documentation. The base rate is about 8.7%.
* Protected attributes `sex` and `age_band` are generated **independently of the target** and stored in separate
  columns that are never passed to the models. They exist only so the fairness dashboard has something to compute.
  Because they are independent by construction, the dashboard demonstrates the metrics, not real-world disparities.
* Splits: stratified 60 / 20 / 20 (train / validation / test). Calibration uses the validation split; every reported
  metric is on the untouched test split. Outlier ranges (p01 / p99) are fitted on training data only and used for the
  in-range flag at scoring time.

## Limitations that no amount of tuning fixes here

* Synthetic data cannot validate a model for real lending. The generator's default mechanism is an assumption.
* Real HELOC outcomes depend on rate resets, draw behaviour, house-price paths and servicing, none of which are modelled.
* Fairness metrics on independent synthetic attributes say nothing about real disparate impact.
* Before any real use: real, licensed outcome data; a documented model-risk-management review; fair-lending testing
  with a defined comparator population; legal review of the reason codes and letter templates.
