INSIDE EQUILEAD

Less mystery. More context.

A guide to the application workflow and what each result means.

Every recommendation
should come with an explanation.

EquiLead explores how home-equity application data, a predictive model, and communication review can fit together in one workspace, with the governance a lender would need around it.

{% for n,title,body in [('01','The application','Twelve financial and credit-history inputs follow the HMEQ dataset schema. Names are kept for the record and are not a prediction feature. No protected characteristic is collected.'),('02','The recommendation','XGBoost produces a class-weighted default score that is compared with the threshold on the model card. Unless a calibrator has been applied, that score is not a calibrated probability and is never described as one.'),('03','The explanation','SHAP describes which inputs moved the model score and in which direction. It is an engineering view: not a causal finding and not a customer-facing reason.'),('04','Adverse-action reasons','For a decline, the features that raised the score are mapped to a reason-code table. Only coded reasons can reach a notice, at most four, and only once compliance has approved the table.'),('05','The communication','Claude drafts a message from the recommendation and the coded reasons. A separate language reviewer can request a rewrite or human review. All messages remain drafts; the app never sends email.'),('06','The human decision','A reviewer records the actual decision, a note, and later the observed outcome. That entry is kept apart from the model recommendation and the language check, and every change is an audit event.'),('07','The model card','Model version, dataset version, training date, threshold and calibration method travel with every decision and appear in the CSV export, so a record can always be traced to the model that produced it.'),('08','Records that cannot drift','Each decision is sealed with a hash chained to the one before it; workspace actions form a second chain. Retention purges keep the hashes of what they remove, so both chains still verify.'),('09','Monitoring and fair lending','Reviewers see input and score drift against the training reference, plus approval and error rates by group with four-fifths and error-gap checks. Group membership for protected classes must come from a governed source, never the form.')] %}
